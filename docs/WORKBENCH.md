# 通用 PID 参数整定工作台

本工程包含 `sdk/`、`pid_agent.workbench` 和独立静态网页。正式桌面环境为 Windows，通信采用电脑主动连接串口或 TCP。自动整定只使用数值算法，不依赖 MATLAB 或大模型。**启动命令为 `python -m pid_agent.workbench`，端口默认 8766**。

## 启动

安装 Python 3.10+，在工程目录执行：

```powershell
python -m pip install -r requirements-workbench.txt
.\open_workbench.cmd
```

也可以不自动打开浏览器：

```powershell
.\start_workbench.ps1 -NoBrowser
# 然后访问 http://127.0.0.1:8766
```

工作台默认只提供连接界面，启动不会运行设备。网页由本地服务托管，无 CDN、前端编译或 Node 运行依赖。`web/index.html`、`app.js`、`style.css` 也能放到独立静态服务器；启动本地服务时通过 `--allow-origin http://localhost:8080` 明确允许其来源。不要直接使用 file:// 打开网页。跨来源访问本地网络还受浏览器自身策略约束，优先使用本地服务同源页面。

若需要重新编译同核心仿真库，安装 GCC/Clang 后执行 `python tools/build_workbench.py`。当前源码包包含本机 Windows x64 的 DLL；其他架构需重建。Python 依赖需预先安装，源码包不冒充无需运行环境的独立 EXE。

## 第一次完整仿真

1. 通信方式选“仿真”，点击连接。仿真使用真实 C SDK 的 PID、协议和实验状态机；对象是增益 1、时间常数 0.6 s、延迟 0.03 s 的速度环，外环测量为速度积分。
2. 选择 PI、位置式，勾选 `kp`、`ki`；上下界设 0、5。当前设备初始参数为零，可以保留。
3. 起步方式选“从对象模型生成初值”，模型保留上述仿真值。试验 6 s，阶跃前 0.5 s，训练幅值 1，验证幅值 0.8，预算至少 10 次/180 s。
4. 点击自动整定。查看基准、搜索和三次独立复验、原始指标与响应曲线。复验通过后可导出 JSON/CSV/C 配置，或显式点击应用参数。

试验结束恢复**开始任务之前设备上的配置**，不会自动把候选写入设备。应用参数只更新 RAM，不写 Flash。关闭网页不停止本地服务任务；停止按钮提交取消请求，等待设备退出和配置恢复。关闭服务会请求停止；进程被强杀/断电时靠端侧心跳退出及设备自身保护。

## 实际设备接入

先按 `sdk/README.md` 接入 SDK 和板级钩子。不是把通用 SDK 直接替换进某个现有项目并烧录：传感器/执行器单位、周期、控制权切换、重启标识和退出动作必须由具体项目提供。

串口支持 USB 转 UART 和系统识别为串口的 USB CDC。TCP 由电脑作为客户端，STM32 或透明传输设备作为服务端，可靠字节流上承载相同协议。串口由本地服务使用 pyserial 打开，网页不要求浏览器支持 Web Serial。

确认设备参数、硬输出范围、两环测量范围、初始位置/速度、心跳超时、记录倍率后再开始试验。正式使用前需在目标板完成编译、周期与负载检查、退出动作和保护验收；本次工程验证没有连接任何实际设备。

## 搜索算法实际实现

一次任务固定类型、形式、功能开关、采样周期、评分权重和搜索边界。只搜索勾选且对当前结构有效的数值；每个候选先量化成 MCU 实际 float32，回读核对后评估。边界支持线性/对数尺度。输出边界、堵转阈值等保护条件不允许作为优化目标自由移动。Kd 和无滤波测量变化率 FFJ 存在线性冗余时，禁止同时搜索。

流程为：**初值 → 两次基准 → 候选实测 → 三次独立复验 → 导出**。次数和计划试验总时间都受预算限制，辨识也计入预算。循环预留复验预算，取消和基础设施故障立即结束，不制造“大罚分”来污染性能模型。

### 四种起步

| 模式 | 实际行为 | 前提 |
|---|---|---|
| 已有参数 | 先重复基准，再搜索 | 已有能完成测试的控制器；不假定它已经最优 |
| 对象模型 | FOPDT/二阶/积分惯性模型生成频响；适用时加入 SIMC PI 初值，再做离散频域拟合 | 使用者提供模型、作用方向和边界 |
| 闭环辨识 | 基准先通过约束，再保持原控制器逐频注入，估计对象频响 | 已有可用闭环和合适的激励幅值 |
| 受限开环 | 逐频注入建立初值，随后转闭环搜索 | 本次显式确认、设备允许、声明稳定/单积分对象 |

从零模式不会把“零增益控制器不发散”冒充已稳定的基准。开环支持的对象类别是用户声明的条件，系统没有自动证明对象开环稳定；不承诺任意未知、开环不稳定对象都能从零自动整定。

频响辨识默认逐频 8 周期，舍弃前 2 周期并去除偏置/线性趋势，联合拟合已知激励、实际输入和输出的正余弦分量。拒绝饱和、信噪不足、窗口差异过大、截断和丢点。窗口一致性是质量检查，**不是统计置信区间**。频域初值使用 SDK 对应的离散积分、微分、测量比例/微分和滤波传递关系，在给定范围内拟合目标带宽与相位裕度；稀疏频点和模型拟合不构成稳定性证明。

### 三种数值搜索器

| 搜索器 | 已实现内容 | 适合的试验条件 |
|---|---|---|
| 约束贝叶斯优化 | Matérn 5/2 ARD GP、观测噪声估计、联合潜变量 Monte Carlo noisy EI、独立约束 GP 可行概率、自适应局部范围 | 小维度、单次实测昂贵、存在测量噪声 |
| 局部模式搜索 | 归一化坐标正负方向、步长缩小、有界随机备用候选 | 参数少、需要直观和较低计算开销 |
| CMA-ES | 加权选择、协方差秩一/秩 μ 更新、演化路径、累积步长适应、边界内拒绝采样、可行性优先排名 | 参数较多、允许较多试验的非凸局部优化 |

这是项目自身的小样本实现，未使用 BoTorch，也不声称与 MATLAB 内部算法相同。贝叶斯可行概率不能当作真实设备安全保证；所有算法都受相同端侧保护。CMA-ES 每代需要多个候选，低预算下通常不适合作为默认。模式搜索含随机备用，因此不宣称严格确定性收敛定理。

重复参数按平均代价、最坏约束选择当前最优，避免只挑单次幸运结果。最终验证独立采集三次；网页默认更换阶跃幅值，API 还支持 1–8 个训练和验证工况。报告明确区分同工况重复与留出工况。只有相同工况才报告描述性相对基准改善，**尚未提供显著性检验或参数优越性的统计保证**。

## 评分与约束

各项按阶跃幅值、试验时长或输出范围归一化：ITAE、超调、尾部平均绝对误差、输出总变化、饱和占比。默认权重为 0.55/0.20/0.15/0.05/0.05；总代价越低越好，显示分数为 `100/(1+cost)`。硬约束另算，不能用其他指标好看来抵消严重超调。

检查完整样本、索引、时间间隔、阶跃前误差与波动，阶跃后至少 20 点、尾部至少 3 点，所有指标有限。负向阶跃也按正确方向计算超调。基础设施错误（超时、溢出、来源不明的非有限数）标为 invalid 并停止，不记录为参数不可行；有效轨迹的约束超限参与约束建模；设备限位、堵转、变化率保护则明确记录 aborted。

每次原始曲线保存到 `results/workbench/<job-id>/trial-XXXX.json.gz`；`report.json` 包括请求、参数、指标、复验、预算和恢复状态。仿真始终带 `simulated=true`。导出的 C 配置保留全部开关、未调参数和串级配置。

## 串级使用顺序

先选择内环，只勾选内环参数，完成整定并显式应用已验证结果；再选择外环，保持内环固定并勾选外环参数，重复辨识/搜索/复验。外环开环模式的“输入”是内环目标，实际执行器仍由内环控制。最后可在已有参数模式同时勾选两环数值做联合时域优化。

当前网页按上述步骤由使用者切换阶段，尚未提供跨两环一键执行并自动比较阶段结果的调度器；双环控制、两环分阶段搜索、外环辨识和联合微调接口均已有实现。这个差异不能包装成“全自动串级整定已经验收”。

## 工程结构与验证

```text
sdk/                         C99 PID、协议、实验状态机、接入示例
src/pid_agent/workbench/
  schema.py                  配置、数值量化、能力与参数范围
  protocol.py / device.py     协议、串口、TCP、同 C 核心仿真
  analysis.py / design.py     评分、频响、离散频域初值、SIMC
  search.py / runner.py       三种搜索器、预算、实验与独立复验
  service.py / server.py      本地任务、导出、HTTP 会话与来源检查
  web/                       无构建静态网页
tests/test_workbench.py       协议、设备、算法、完整服务集成测试
tests/workbench_core_test.c   PID 数值性质和 CRC 测试
```

```powershell
python tools/build_workbench.py
$env:PYTHONPATH='src'
python -m unittest discover -s tests -p test_workbench.py -v
```

32 项 Python 集成测试与 C 核心测试已在 Windows 主机通过。资源计量是主机编译结果，不能当作 MCU WCET；串口测试使用模拟串口流，TCP 为本机回环设备，真实 USB/UART/网络外设仍需硬件验收。
