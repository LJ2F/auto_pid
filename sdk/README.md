# 通用 C99 PID SDK

详细文档：[完整使用与真机接入说明](../docs/USER_MANUAL.md) · [逐函数参考手册](../docs/FUNCTION_REFERENCE.md)。下面保留最小接入概要。

将 `include/pt_sdk.h` 与 `src/pt_pid.c`、`src/pt_protocol.c`、`src/pt_runtime.c` 加入 STM32 工程，添加 include 路径。无 HAL、RTOS、C++、动态内存依赖。数学库由工具链提供；不要启用破坏 `isfinite` 语义的 `-ffast-math`。

## 最小接入

参见 `examples/control_task.c`。使用者负责传感器单位、实际输出、通讯队列和退出动作。初始化一次，在实际固定周期的控制任务里调用 `pt_runtime_tick`；将返回值送执行器前，必须确认状态仍是 `PT_RUNNING`。正常完成、限位、超时、停止等退出由 `pt_exit_fn` 决定刹车、卸载、保持或切回原控制，不能通用地假设“输出零就安全”。示例 `board_normal_control` 必须服从应用自己的实验退出锁存状态，不能在下一 tick 自动重新驱动故障对象。

接收 ISR/网络线程只写接收队列。`receive`、`tick`、配置和停止属于**同一个任务上下文**；SDK 不提供跨线程互斥。发送回调须在返回前复制整个报文至有界 TX 队列，不能把 SDK 内存直接交给异步 DMA。队列满应退出实验，不能默默丢帧并继续输出。

`pt_runtime_set_hardware` 设置实际基本周期和硬输出范围。主机提交周期必须匹配。`boot_id` 每次重启必须不同，可由应用持久化启动计数或可用的启动随机源产生；固定为 1 不满足旧报文隔离契约。端侧默认禁止开环，只有设备集成者明确允许后才调用 `pt_runtime_allow_open_loop`。

SDK 本身不提供回零或机械复位。主机每次试验重新初始化控制器状态；**真实对象的初始状态要由设备应用恢复到试验工作点**。评分检查阶跃前误差与波动，无法达到时会拒绝评分。速度/位置、角度、电流单位由应用统一；参考 PID 的逐周期 Ki/Kd 不应直接当作本 SDK 的连续时间增益。

## 独立使用 PID

```c
pt_pid_config c;
pt_pid pid;
pt_pid_defaults(&c);
c.kind = PT_PI;
c.kp = 1.0f;
c.ki = 2.0f; /* 每秒积分增益 */
c.output_min = -5.0f;
c.output_max = 5.0f;
pt_pid_init(&pid, &c, 0.0f);
float u = pt_pid_step(&pid, target, measured, 0.001f);
```

支持 P/PI/PD/PID、位置式/增量式、矩形/梯形积分、比例对测量、微分对测量、输出/微分一阶滤波、变速积分、积分限幅、条件积分、反算抗饱和、死区、堵转和 FFJ/FFB。积分/微分用实际固定 `dt`，滤波参数是秒；FFJ 乘测量变化率，FFB 乘测量值，保持参考代码定义。

比例对测量定义为 `P=-Kp*y`，等价设定值权重 β=0；普通比例为 `Kp*(r-y)`。没有 I 的 P/PD 配合 β=0 不产生设定值比例响应，这是结构选择的结果。增量式保存未限幅的代数和，防止 P/D 饱和后留下永久偏置；抗饱和显式作用于积分。死区内输出零、积分清零，零仍经过输出范围约束。

变速积分保留原代码“误差与积分同向时才衰减”的行为；`integral_b` 以下全速，随后在 `integral_a` 宽度内线性降至零。没有额外发明另一套积分分离开关。

## 串级与实验

`loop[0]` 为内环，`loop[1]` 为外环。外环每 `outer_divider` 个基本周期更新，输出作为内环目标；外环输出范围单位是内环目标单位。调内环时旁路外环，但仍检查两个实际测量值的边界。调外环时保持内环参数固定；已有参数模式可显式同时勾选内外环做时域联合优化。

外环开环辨识仅旁路外环 PID，保持内环运行，向内环目标注入偏置加激励；这时必须事先得到可用内环参数。单环开环则向实际执行器注入激励。两种模式都要求端侧许可和本次主机确认。

端侧完成波形生成、输出范围、测量范围、输出变化率、堵转、非有限数、采样溢出与通讯超时处理。`max_slew` 超限会**终止**，不是将波形斜率悄悄裁剪。微控制器调度延误/中断饥饿时的软件退出不构成独立硬件保护；应用负责固定周期调度、看门狗和硬件限位。

## 资源与吞吐

默认固定缓冲帧 1024 字节、64 个 60 字节采样。本机 x64 `sizeof(pt_runtime)=8640` 字节；ARM 实际值需目标编译确认。可用宏 `PT_FRAME_MAX`（至少 238）、`PT_SAMPLE_CAPACITY` 调整，所有编译单元须一致。控制器本体比实验记录/报文缓冲小，纯控制应用可仅编译 `pt_pid.c`。

记录速率为 `1/(dt*decimation)`。串口 8N1 有效上限约 `baud/10` 字节每秒，另有帧/ACK/请求开销；主机按每点 75 字节及 75% 预算预检。115200 不适合 1 kHz 全量记录，增大记录倍率不会改变实际控制周期。主机每次 READ 批量取样；任何丢失、重复和溢出都不会被当作完整曲线。

## 协议与验证边界

帧格式与用户提供的 transfer_protocol / verification_algorithm 兼容，应用命令默认 `0x7D50`。应用字段和握手见 `../docs/WORKBENCH_PROTOCOL.md`。此 SDK 的应用消息需要固件加入调试服务；旧固件只会解析帧并不意味着已支持整定命令。

已完成本机 C99 严格编译及同核心仿真。还没有针对实际 STM32 工程交叉编译、烧录、DMA、串口设备、电机、执行时间与 RAM 峰值验收。示例保留板级钩子，由工程接入方实现。
